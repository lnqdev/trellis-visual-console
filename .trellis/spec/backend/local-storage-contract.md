# 本机存储可执行合同

## 范围

修改应用数据目录、`registry.json`、`snapshots.json`、`updater-state.json`、版本、迁移、原子写或清理时必须遵守本合同。源项目 `.trellis` 不是应用存储。

## 当前合同

- 固定文件为 `<应用数据目录>/registry.json` 和 `snapshots.json`，当前根版本为 2。
- macOS 目录为 `~/Library/Application Support/Trellis Visual Console`。
- Windows 目录为 `%APPDATA%\Trellis Visual Console`；`APPDATA` 缺失时回退用户 Roaming 目录。
- `TRELLIS_VISUAL_CONSOLE_DATA_DIR` 仅用于开发和隔离验证；相对值先解析为绝对路径。
- 注册表与快照的完整读改写由一个互斥锁串行保护。
- 保存使用 UTF-8、同目录临时文件、文件同步和原子替换。
- adapter 独立维护 `updater-state.json` 版本 1，只保存上次自动检查时间；损坏内容隔离，更高版本拒绝覆盖，不进入 `trellis-core` 存储锁。
- 未来版本必须停止初始化并保留原字节，禁止当作损坏恢复。
- v2 损坏数据隔离为 `.corrupt-*`；恢复行为不得影响版本不兼容文件。

## 版本 1 迁移

1. 完整读取并严格校验 v1 注册表；失败时不写任何文件。
2. 原字节备份注册表和快照，备份名不覆盖既有文件。
3. 写入 v2 空快照，旧快照只备份、不作为运行数据。
4. 最后提交 v2 注册表，保留项目 ID、路径、名称、状态和时间。
5. 缺失快照项目在后台重建；中断重启必须幂等继续。

## 清理

清理只能删除固定应用数据目录中的注册表、快照和日志。不得遍历、修改或删除已登记项目。

## 验证

临时目录至少覆盖首次创建、v1 双备份、迁移中断恢复、损坏隔离、未来版本保护、并发保存、日志共存和源项目零写入。

## 场景：移除单个已登记项目

### 1. 范围 / 触发条件

- 新增或修改项目移除、注册表过滤、快照清理及其失败补偿时适用。

### 2. 签名

```rust
ProjectCatalog::remove_project(&self, project_id: &str) -> Result<bool, ProjectCatalogError>
```

### 3. 合同

- `registry.json` 是登记状态的权威来源；返回 `true` 表示项目原先存在且已移除，返回 `false` 表示项目不存在。
- 操作必须持有现有读改写互斥锁，先保存过滤后的注册表，再保存删除对应键后的快照。
- 快照保存失败时必须尝试恢复旧注册表；迁移待重建集合只在两份文件均成功后清理。
- 全流程只访问固定应用数据目录，不读取后删除、移动或写入源项目及其 `.trellis/`。

### 4. 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| 项目 ID 存在，两份文件保存成功 | 返回 `true`，注册表和快照均不含该 ID |
| 项目 ID 不存在 | 返回 `false`，不写文件 |
| 注册表保存失败 | 返回存储错误，旧注册表和旧快照保持可见 |
| 快照保存失败、注册表恢复成功 | 返回存储错误，恢复原登记状态 |
| 快照保存失败、注册表恢复也失败 | 返回存储错误；注册表仍是重启后可见状态的权威来源 |

### 5. Good / Base / Bad Cases

- Good：在锁内过滤两份 v2 数据，注册表先提交，快照失败时恢复注册表，成功后清理迁移待重建 ID。
- Base：删除不存在的 ID，返回 `false` 且文件字节不变。
- Bad：先删快照再删注册表，或遍历源项目执行文件删除。

### 6. 必需验证与断言点

- 使用隔离应用数据目录登记、移除、重启，断言项目和任务中心均不再出现该 ID。
- 注入两次保存的失败点，分别断言注册表失败零提交、快照失败触发注册表补偿。
- 移除前后计算源项目 `.trellis/` 全文件哈希，断言完全一致。
- 重新登记同一路径，断言按正常登记流程生成新快照。

### 7. Wrong vs Correct

#### Wrong

```text
删除源项目目录 -> 删除快照 -> 保存注册表
```

#### Correct

```text
持有应用存储锁 -> 校验登记 -> 保存过滤后的注册表 -> 保存过滤后的快照
-> 成功后清理迁移状态；失败则补偿注册表
```
