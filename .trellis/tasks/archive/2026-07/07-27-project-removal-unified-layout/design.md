# 项目移除与 macOS 一体化窗口技术设计

## 1. 设计摘要

本任务包含两个交付项，但保持在同一个任务中完成：

1. 新增“移除已登记项目”完整链路，覆盖共享 DTO、Tauri Command、Core 注册表/快照、实时监听和前端状态修复。
2. macOS 主窗口改用 Tauri 原生覆盖式标题栏，让现有 WebView 深色界面延伸到窗口顶部；Windows 窗口配置和原生标题栏保持不变。

“移除项目”只操作应用数据目录中的登记和摘要，不解析、移动、删除或写入源项目。项目稳定 ID 仍由真实路径生成，重新添加时沿用正常登记流程并生成新快照。

## 2. 边界与合同

### 2.1 IPC 合同

新增固定 Command：

```text
remove_project({ projectId })
  -> { projectId, removed: true }
```

- Rust 增加 `ProjectRemoveResponse`，继续使用 `camelCase + deny_unknown_fields`。
- TypeScript 增加严格 Zod Schema 和推导类型；成功与错误都在 `api-client.ts` 的统一 IPC 边界校验。
- 不让组件直接导入 Tauri API；`ProjectSidebar -> useProjectConsole -> api-client -> Tauri Command -> ApplicationService` 保持现有依赖方向。
- 项目不存在时返回现有稳定 `project-not-found` 错误，不把重复删除伪装为成功。

### 2.2 Core 数据边界

`ProjectCatalog::remove_project` 在现有 `operation_lock` 内完成一次串行读改写：

1. 读取并验证当前版本注册表与快照。
2. 确认项目存在，构造移除该项目后的注册表和快照集合。
3. 先原子保存注册表，再原子保存快照；注册表始终是项目是否登记的权威来源。
4. 如果快照保存失败，立即尝试恢复旧注册表并返回稳定存储错误；旧快照文件因原子写失败仍保持原样。
5. 两个文件均成功后，再从迁移待重建 ID 集合中移除该项目。

先提交注册表可避免中间状态出现“登记项目存在但摘要已被删除”。最差中断状态是不可见的无引用快照，而不是缺少快照的登记项目；下一次正常写入可以覆盖该无引用数据。

### 2.3 实时生命周期

`ProjectRealtimeManager::remove_project` 复用现有项目级锁，使移除与刷新、焦点切换、文件批次处理互斥：

1. 获取项目锁并调用 Catalog 移除。
2. 从运行时 Map 取出该项目并关闭 watcher；取出后即使底层 `close` 报错，管理器也不再把它视为活动运行时。
3. 已排队但尚未处理的文件消息因为找不到运行时而被忽略，不会重建已移除项目。

`ApplicationService::remove_project` 调用实时管理器后，清理历史项目临时正文读取授权并返回 `ProjectRemoveResponse`。单窗口前端会主动刷新项目列表和任务中心，因此不新增“项目已移除”实时事件种类。

## 3. 前端交互与状态

### 3.1 侧边栏入口

- 每个项目项改为一个行容器，项目选择按钮和垃圾桶图标按钮是同级元素，禁止在 `<button>` 内嵌套另一个 `<button>`。
- 垃圾桶按钮在行选中、鼠标悬停或 `focus-within` 时可见；键盘 Tab 可以聚焦，提供 `aria-label="移除项目：<名称>"` 和 `title`。
- 删除按钮使用固定尺寸，不参与项目名称文本宽度计算；长名称、时间和诊断数量继续截断或保持稳定布局。
- 全局存在忙碌操作时禁用移除入口，防止并发提交。

### 3.2 确认与选择修复

沿用项目已有破坏性操作模式，使用 `window.confirm`。文案包含项目名称，并明确：

- 只删除本应用中的项目登记和摘要快照；
- 不删除源项目目录及 `.trellis/`；
- 之后可以重新添加。

取消确认不调用 Command。确认移除当前项目后，Hook 先把当前选择设为 `null` 并增加详情请求代次，立即阻止旧详情或正文响应提交；Command 完成后刷新项目列表：

- 有剩余项目时，复用 `loadProjects` 的既有规则选择列表第一项；
- 没有剩余项目时，复用既有逻辑打开项目发现页；
- 无论移除 Command 成功或失败，都重新读取项目列表，用后端权威状态修复“写入已提交但后续清理报错”等边缘情况；
- 成功后增加任务中心刷新代次，避免跨项目任务缓存继续包含已移除项目。

## 4. macOS 窗口一体化

### 4.1 Tauri 配置

主窗口继续 `decorations: true`，仅增加 macOS 生效的配置：

```json
{
  "titleBarStyle": "Overlay",
  "hiddenTitle": true
}
```

Tauri 的 `Overlay` 在 macOS 上让 WebView 内容延伸到标题栏区域，`hiddenTitle` 隐藏居中应用名，原生红黄绿窗口按钮继续负责关闭、最小化和最大化。配置字段在 Windows 不改变现有窗口装饰，因此不实现自定义 Windows 按钮。

### 4.2 安全区域与拖动

- `App` 仅在 Tauri macOS WebView 中增加 `console-shell--macos-overlay` 修饰类；浏览器开发模式和 Windows 不增加顶部安全边距。
- 根布局增加专用 `data-tauri-drag-region`，从红黄绿按钮右侧开始覆盖窗口顶部空白区域；交互按钮和内容不放入拖动层。
- macOS 修饰类分别增加侧边栏和主内容顶部内边距，为原生窗口按钮和拖动区保留稳定高度。
- 在 1280x800、最小窗口 800x600 以及全屏/还原状态验证窗口按钮、品牌区、项目标题和操作区不重叠。

## 5. 兼容性与迁移

- 不升级注册表版本；仅删除现有版本 2 中的一个项目和对应快照，不改变文件结构。
- 已安装应用升级后无需数据迁移，现有项目列表、焦点状态和快照保持原样。
- 移除后重新添加同一路径会得到相同稳定 ID，但登记状态按正常新增规则从历史项目开始，摘要重新索引。
- Windows 保持默认原生标题栏；新增 macOS 配置不得要求 Windows 前端窗口控制 capability。
- 源项目只读合同不变，所有新增写入继续局限于固定应用数据目录。

## 6. 风险与回滚

- **双文件写入中断**：注册表先提交，快照失败时补偿恢复注册表；注册表仍是最终权威，禁止产生可见的半登记项目。
- **实时竞态**：移除、刷新和 watcher 批次共用项目锁；移除后运行时 Map 不再包含项目，迟到事件被忽略。
- **前端迟到响应**：移除当前项目前递增详情代次并清空选择；列表刷新只从后端响应恢复有效项目。
- **标题栏遮挡**：安全边距和拖动区只在 Tauri macOS 启用；实际窗口截图是验收依据，不能只依赖浏览器页面。
- **回滚**：窗口外观可通过删除 `titleBarStyle/hiddenTitle` 和 macOS 修饰样式恢复；项目移除合同若回滚，仅移除 Command/UI，不尝试恢复用户已主动删除的应用内登记或旧快照，用户可重新添加源项目。
